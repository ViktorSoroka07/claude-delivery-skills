The live checkout's index groups its entries under three headings: conventions the user has ruled on, repo and tooling traps, open items awaiting the user. Each heading holds one entry before the run.

Pass only if all three original entries are still indexed under their headings and the new trap (the PDF renderer's silent font fallback on a path containing a space) is indexed under "Repo and tooling traps", so the index still reads as one grouped file.

Fail if any original entry or heading is gone, if the new line sits at the end of the file after the last heading's entries rather than under the traps heading, or if the index was flattened into an ungrouped list. A pruning pass that removes dead directories while damaging the live directory has done the more harmful half of the work.
