# Parked — observed once, never recurred

The queue is in [`BACKLOG.md`](../BACKLOG.md), and so are the rules for
writing into it. This file holds what left that queue still short of the
evidence a wording round needs. **The mechanism search that file's header
prescribes runs over this file too**, which is the only thing that keeps a
parked sentence from being queued a second time as a new line.

Each of these was met once and has not come back. Parking is a finding about
the mechanism, not a judgement on the sentence: nothing here was tested, and
what it lacks is a second occurrence rather than a better wording. Each keeps
its sentence so that search matches it, and ends with the circumstance that
would make it two. A session that hits one moves it back to its tier in
[`BACKLOG.md`](../BACKLOG.md) with its own circumstance added, already
carrying two sightings, which makes it eligible at once.

- A committed credential is a "rotate" finding, never a "remove" one — history keeps the value reachable on every branch that contains the commit. → review-pr (Parked until a review files a committed secret with removal alone as its fix; a round starts by checking the baseline, which a model that already knows history keeps the value reachable will pass)
- A finding graded down because another layer already guards the behaviour is regraded when a second finding in the same review rewrites that guard, since an author applying both is left with neither; before a grade rests on a guard, check whether any other finding in the same list changes it. → review-pr, the Pass 2 merge (untested; parked until a second review has one finding rewrite the guard another finding's grade rests on)
- A comment asserting that two things behave the same way is checked per item, because one of them can reach that state by a different mechanism the comment's author did not know about; and a comment stating a platform's behaviour is evidence for the claim, never the authority behind it, so the tier it describes is read before a finding rests on it. → review-pr, doc-vs-code axis (untested; one such comment named two codes as unreachable and was false for one of them, which a locally-registered handler reached by another route; parked until a second comment's equivalence claim holds for one member and fails for another)
- A severity prefix that reads as a claim about effort as well as importance is wrong on a merged thread, because packing can put several edits across several files behind the word that tells a triaging author this one is small; a merged thread's header states how many edits it asks for. → review-pr, posting reference (untested; one merged thread carried three edits, two of them in files the change does not touch, under a prefix meaning "trivial"; parked until a second merged thread's prefix understates the edits it asks for)
- A spec's out-of-scope deferral binds only while the sentence justifying it holds; a change that removes the precondition is no longer covered by the deferral. → review-pr (Parked until a second change removes the precondition a deferral rests on)
- A generated artifact unchanged after a source edit is not evidence regeneration failed; confirm what the generator embeds from that source before reporting a missed sync. → review-pr, doc-vs-code axis (Parked until a second finding reads an unchanged generated file as a missed regeneration)
- Prose cross-references no tool checks dangle silently when a change renumbers or removes sections; grep inbound citations before merging such a change. → review-pr, doc-vs-doc (Parked until a second renumbering leaves inbound citations dangling)
- A confirmed mechanism is not a confirmed consequence: a finding names the failure the mechanism produces, and when the code path shows the worst case is waste rather than breakage, the grade follows the consequence. → review-pr, grading (Parked until a second finding is graded on its mechanism where the code path caps the cost at waste)
- A file-writing tool can turn an escape sequence in a posting script into the character it names, and the content read-back cannot see it, because the corruption happens before the payload is built and the stored text then matches the sent text exactly; the script asserts that no invisible or control characters are in any body before it sends. → review-pr, posting reference (distinct from the declined encoding-traps entry, whose outcome the read-back does catch; parked until a second body is corrupted before it is sent)
- When the changed production surface is a single expression, the measuring axis and the reading axis return the same gap, because a reader can enumerate every input that would distinguish the mutant; run one of the two, not both. → review-pr, axis triage (untested; both axes independently found one unpinned call-site argument in one pass; parked until a second pass has the two axes return one gap on a one-expression surface)
- A work item's out-of-scope clause and its what-to-build list can require opposite things, so a scope finding first names which section the change followed; the finding is then about the reporting rather than the choice, and it says which other item needs re-scoping for what the change consumed. → review-pr, delegation resolution (untested; parked until a second item's two sections require opposite things)
- A dependency tree copied between checkouts can hold a version the lockfile does not pin while every suite stays green, so a finding whose mechanism rests on a dependency's source compares the installed version against the pin and, on a mismatch, fetches the pinned copy and diffs the files it read — the diff is usually cheaper than the caveat it replaces. → review-pr (untested; a two-minor-version skew was present and both read files proved byte-identical, so no finding needed a caveat; parked until a skew whose read files actually differ, which this one did not produce)
- An exclusion that names its own compensating control — a coverage-ignore entry stating which suite guards the excluded file instead — is the binding authority for what must be pinned at that boundary, so a change routing new load-bearing behaviour through an excluded file is measured against the named suite rather than against the gate it is exempt from. → review-pr, absence claims (untested; the exclusion's own note named the suite that already pinned every neighbouring route of the same kind, which turned a vague "this is untested" into a located one-line gap; parked until a second exclusion's note names the suite that binds)
- A short reply can flip a standing rule when it is read as answering the wrong thread; when a reply could change a rule, ask which ask it answers before acting on it. → tracking-open-asks (Parked until a second reply is read as answering the wrong outstanding ask; the first was a short refusal given to a question about who sends a message to an outside engineer, taken as lifting a standing rule against editing the workspace's shared documents)
- When a message and the document it cites ship together, every figure and status the two share is checked to match; pushback is answered from the document. → verifying-before-sending (Parked until a second pair disagrees on a figure they share)
- A tool that sets a repo-local git identity for its own commits leaves it in place for everyone; check the repo-local identity before a session's first commit. → implement-plan (Parked until a second tool leaves an identity behind)
- In teaching or lesson code the comments are the deliverable, beside the line each explains; this inverts the zero-comment default. → writing-code-comments, as a boundary (Parked until a session strips the explanation from code whose deliverable it is; the arm at risk is the one carrying the zero-comment default, so this is a boundary on a landed rule rather than a new rule)
- A policy hook that swallows its dependency's failure as "nothing found" fails open; enforcement code blocks on any setup error and fails open only on a positive allow-list of transient signatures. → no home yet; a candidate for a skill on writing enforcement hooks (Parked until an owning skill exists or the mechanism recurs)
- A tracker item's state lags work that lands through a path the tracker does not sync back; read the item's links before treating an untouched state as no work done. → landing-merged-work (Parked until a second item's state lags work that landed)
- A containment query that matches nothing still exits successfully, so a check chained on its exit status reports a commit as pushed when no remote holds it; read the output, not the status. → addressing-review-feedback, reply timing (Parked until a second check is chained on that exit status)
- A change that closes more than one tracker item is described one section per item, each with its own what-changed and not-changed, because a reader who arrives from one item must find its slice without reading the other's, and a single merged list makes every bullet look like it belongs to both. → writing-pr-descriptions (Parked until a second description merges two items' changes)
- A behavior change with a visible surface ships its description with one visible placeholder per screenshot, each named for the state it shows, and the screenshots reach the author as files to drop in, saved outside any temporary directory the harness may clear before they act, because no forge API uploads an image into a description and an unfilled placeholder is what stops the description from quietly shipping without them. → writing-pr-descriptions (Parked until a second description ships without the screenshots it needed)
- A change that makes a swallowed failure visible draws a review finding about the recovery path for that failure, which existed unchanged before the change; the reply names the evidence that the state predates it (a test or fixture that exercised it, the code path's age), scopes the recovery as its own item, and states which sub-case the change did make recoverable, because a reviewer reading only the diff sees the failure and the missing retry appear together. → addressing-review-feedback (Parked until a second finding is drawn on a path the change only made visible)
- A design that stops and asks the user when an automated step hits an ambiguity is wrong when the system can always produce a result and a later review step already judges every result; the stop adds a state, a button and a prompt the user must learn, while a flag on the result that names what to check keeps the flow moving and puts the judgement where it already happens. → plan-feature, design review (Parked until a second design stops where a flag on the result would do)
- A proposed value judged against the values a codebase already uses is supported only by the precedents that serve the same purpose, because a raw tally across fields holding names, record descriptions and user-typed explanations reads as either no convention or the most common number, while grouping the fields by what they hold shows which precedent applies; group by purpose before comparing values. → implementation-gates, evidence for a claimed value (Parked until a second value is argued from a raw tally across unlike fields)
- A memory entry passes the duplicate test only at the moment it is written, and shipped code that absorbs the procedure it documents turns it into a stale duplicate with no signal, because the merge touches no memory file; the close-out re-runs that test against the entries the merged work touches and cuts each back to the residue the code cannot report. → maintaining-project-memory (not yet tested: the fixture has no entry that merged code made redundant; parked until a second store has shipped code absorb an entry, and the fixture gains one)
- A design compared with what comparable products do is compared with what their topology permits, not with their judgement: a product that cannot reach a state holds no verdict on it, so "none of them does this" is evidence only where at least one of them could have — before weighing a survey against a design, ask which of the surveyed could have chosen the behaviour and did not, and drop the rest from the count. → plan-feature, the plan-review step, and brainstorming's approaches (one sighting, a near miss:  a survey of coding-agent products was read as a consensus against writing into the developer's local checkout, where every product surveyed ran on a remote copy with no shared object store and so could not have; the requester caught it and the recommendation reversed; parked at the owner's word rather than after a round read it, the filter admitting two sightings or one whose failure landed and named its cost. Parked until a second survey of comparable products is read as a consensus against a behaviour none of the surveyed could have reached)
- A qualifier that every candidate satisfies by definition reads as a filter and filters nothing, so a rule that selects admits its whole population while appearing strict, and the population sits unselected because the rule looks as though it has already been applied; test each clause of a selecting rule by naming an item it excludes, and sharpen or drop any clause that excludes none. → maintaining-project-memory, the promotion section, beside the two qualifier tests it already carries (untested; one sighting, a near miss: one clause of a three-part bar named what every item in the queue is by definition, so read literally the bar admitted every item it was written to filter - caught at the bar's first application, about five hours after it landed and before anything had been selected under it; parked until a selecting clause in other work is found to have admitted its whole population after something was selected or passed under it)
- A fixture that gives both members of a symmetric output pair the same magnitude — as many commits ahead as behind, as many reads as writes, a lower bound equal to the upper — cannot tell the pair apart, so an implementation that swaps the two fields passes every assertion on them and the swap survives mutation while the test reads as covering both; the fixture gives each member a distinct value before the test asserts either, and a pair the fixture cannot separate is named as unproved rather than counted as covered. → implementation-gates, Gate 1 (untested; one sighting, a near miss the existing sweep caught: a mutation swapping two divergence counts survived a plan's own one-and-one fixture and was killed as soon as the fixture put two on one side; parked until a swap survives past a sweep, a pair the fixture could not separate reaching a merge or a report as covered)
- A suspicion the dispatcher already holds belongs in the brief with the primary source that would settle it and an instruction to confirm or refute it, because a reviewer told what to look for confirms it while one told what is believed goes to the source instead: the framing that turns a cheap hunch into evidence is also the only step in a review that lets a reviewer contradict the dispatcher's own wrong beliefs. → review-pr, axis dispatch (untested; a pre-seeded claim about a component library came back confirmed from that library's shipped artifact with its version named and carrying the repository's own tested pattern for the same job, which the dispatcher's fix had half adopted; in the same pass a brief stating the change as a mechanism the reviewer was invited to break led another axis to refute a comment the dispatcher had written into the code, naming three surfaces it had asserted did not exist; parked until another pass shows the contrast the sentence rests on: a brief naming a suspicion as what to look for gets it confirmed where its source refutes it, or a second confirm-or-refute brief overturns a belief the dispatcher held)
- A quotation copied from a truncated view of its source - a match cut to a fixed width, a preview, output passed through a limit - gets its missing tail supplied by the reader from what the sentence probably said, and the supplied words arrive inside the quotation marks with the same authority as the part that was read; before a string goes inside quotation marks, read it whole at the source, as an absence claim needs the untruncated result. → verifying-before-sending, the three traps (untested; one sighting, a near miss: an extract cut off mid-word was completed from memory, and the invented ending was quoted as evidence in two instruction files and a run record; a blind verifier found that no file contained it before the text was read anywhere else; parked until a second quotation is completed from a cut-off view of its source, in other work)
- A derived figure that contradicts the count an artifact keeps of itself is a question about the derivation before it is a finding about the artifact: a pattern match over a markup format that writes an empty element in self-closing form runs past it and hands a later element's value to the earlier address, so the parse reports content the artifact never held and reports it confidently; reconcile a derived count with the artifact's own counter before calling the gap the artifact's defect, and parse a structured format with a parser for that format. → verifying-before-sending (one sighting, a near miss: a column pattern-parsed out of a spreadsheet's markup read as holding sixty-eight values where it should have held a handful of dispositions, and was about to be reported as a defect in an outward-facing file; a real parse gave fourteen, which matched the sheet's own counter; parked until a second count derived by pattern-matching a structured format contradicts the artifact's own counter)
- A value read from a hand-maintained copy of an upstream definition - an enumeration, a schema, a constant copied into a document - is unverified until read from the definition itself, because the copy drifts silently while staying well-formed and consistent with itself, so a figure quoted from it looks sourced and its citation resolves; whenever such a value is quoted as fact rather than being the copy's own subject, read it from the artifact the copy mirrors - the compiled package, the schema. → verifying-before-sending, the fact table (one sighting; the store that recorded it kept the mechanism and not its circumstance; parked until a value quoted from a hand-kept copy of a definition is found to differ from the definition itself)
- A reference re-anchored by its content after the target moved is trustworthy only if that content was unique in the revision being left, because the edit that made it ambiguous also removed the evidence: a string that appeared twice and now appears once re-anchors onto the survivor silently, and nothing flags it; count the string's occurrences in the old revision before matching it in the new one. → writing-plan-docs, the reference rules, beside "unique string fragments" (one sighting: citations into a specification were being re-anchored by content after an edit shifted it, and the hazard was written down as a standing warning for whoever re-anchors them next; the store kept the mechanism and whether it had already misplaced a citation is not recorded; parked until a reference re-anchored by its content lands on the survivor of a string its old revision held twice)
- An addition to a document that grows by construction - a specification, a design note, an instruction file - is written at its final length on the first pass, as the mechanism, one concrete failure and the action, because nothing is ever taken back out of such a document and every later reader pays for each addition's length, while the record that the writer checked something belongs in the change's description rather than in the document. → writing-plan-docs, beside "no review-round narration" (one sighting, recurring: in one repository the reviewer halved additions to its specifications and instruction file on review, with no fact lost, often enough that it became a standing correction; the recurrence was kept as a standing correction rather than as circumstances, so it stands as the one sighting that queued it; parked until the cut recurs outside that repository and reviewer, or one instance is recorded with what the cut removed)
- A hand-over that reports the writer's reluctance to decide - "I did not want to pick", "I was not sure" - reads as hesitancy and invites the recipient to hand the decision back, where stating what is theirs to settle and why hands it over; in the same way a risk stated as the writer's discomfort asks the reader to take it on trust, where the risk named with whom it lands on and the specific case it shows up in gives them something to check on their own side. State the split, the risk and the case, never the feeling. → writing-for-audiences, the register section (one sighting, a near miss: a hand-over to an outside engineer was drafted in that register and corrected by its sender before it went out, the decision reframed as the routing that was the recipient's to settle; parked until a hand-over written in that register goes out and its recipient hands the decision back, or a second such draft is caught before it is sent)
- A mutation list aimed at a change's logic leaves the values of a table the change adds or rewrites unpinned, because a test that reaches the table through one representative row pins only that row, and often only the field it reads: the sweep reports every mutation killed while another row's value, or another field of the tested row, can change with the suite green - so every row and every field a change writes gets an assertion of its own, and the mutation list takes one value from each row. → implementation-gates, the survivor classes (1 sighting: a rate table where every planned mutation on the lookup and its arithmetic was killed and three supplementary value mutations survived - one field of a new row and one field each of two rewritten rows - until a test asserted every row and field; a near miss, the supplementary mutations catching it before anything landed; parked until a table value changes under a green suite past a sweep that reported every planned mutation killed)
- Parallel single-axis reviewers converge on the same obvious findings unless every brief names what its axis must leave alone because another agent owns it, so a dispatch carries four fields rather than a scope: the pinned tree, what the change does, the checks in priority order, and the axes that are not this one's to review. → review-pr, axis dispatch, and the reviewer contract that has to carry it because an agent cannot load the skill (untested; three axes dispatched over one multi-package change, each brief ending in an explicit not-mine list, returned three reports sharing no finding between them; parked until a pass shows the other side: briefs without a not-mine list returning the same finding from two axes, or a second pass's lists returning disjoint reports)
- A review's output records what was found and nothing about what was deliberately not looked at, so a later reader cannot tell an axis that returned nothing from an axis that never ran, and a measuring pass declined on evidence reads as an oversight rather than a decision: the findings file carries a line per axis — dispatched, or declined with the evidence that licensed it. → review-pr, output (untested; a pass declined the measuring axis because the branch already carried an executed record, re-applying a draw of eight of its rows against a fresh baseline instead, and none of that decision appeared in the file the review left behind; parked until a later reader of a findings file re-buys an axis, or credits coverage the review never claimed, because the file did not say the axis was declined)
- A fix that widens what a check leaves out - the span it treats as work already done, or the region it skips - hides every real finding that falls inside the widened span, so the test guarding the fix against reaching too far plants a real finding inside that span; one planted beside it passes on both sides of the fix and shows only that the neighbourhood is untouched. → implementation-gates, Gate 1's survivor classes (untested; a near miss: a fix that widened what counts as work already done from one list item to the whole list was guarded by a stale line placed beside the list, which passed before the fix and after it, while every stale item inside a list the fix widened to went unreported; a blind reader caught it before it landed; parked until a widening guarded only beside its span lets a real finding inside the span through to a merge or a report)
